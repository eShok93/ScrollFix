# Privacy and permissions

ScrollFix works locally. The repository contains no analytics SDK, network client, account system, or telemetry endpoint. It does not persist a history of scroll or gesture events.

To change scroll direction across applications, the app creates a Quartz **session event tap** for scroll-wheel events. It infers their source from scroll phases and optionally changes vertical deltas in memory. This tap also observes pointer movement, mouse-button presses and modifier changes to cancel pending wheel motion. That scroll tap does not subscribe to key-down or key-up events. The separate enabled Home/End feature does subscribe to keyboard down/up events, reads keycodes and modifiers for navigation routing, and posts marked synthetic key pairs for accepted replacements. It does not read character payloads or store typed text; other keys remain native. Secure input and uncertain focus prevent translation. Optional Windows-style autoscroll creates a separate tap for mouse-button presses. Smooth wheel mode and active autoscroll post synthetic scroll events. macOS grants the taps through a broad Accessibility or device-control permission and may require separate Post Event access. That access is checked or requested only for an enabled feature that sends events, after interception access is available. Native and Direct wheel mode need no deferred posting. The wording in System Settings describes what such permissions *could* allow, not a narrow permission limited to scrolling. Review the source before granting them.

With Autoscroll enabled, the first middle-button down performs a bounded public Accessibility hit-test at the event position. It reads element roles and parents to preserve native middle clicks on links and controls. The hit element's PID is compared with ScrollFix's own PID so its click-through marker does not cause a capture. No URL, page text, title or control value is read; no Accessibility action is performed. AX objects are released after the lookup and no page tree is retained. Incomplete or slow lookups leave the original click native. The route of an open middle-button pair is held in memory; no click is copied or replayed. This uses the existing broad Accessibility access and adds no private API or permission category.

The app stores control preferences through UserDefaults: **Mausrad**, **Mittelklick-Scrollen**, wheel-feel mode, scroll distance, Home/End options and app exceptions. The optional internal-trackpad test mode is available only in QA builds. Login registration uses macOS Service Management and is unavailable in QA builds. The app reads macOS's shared natural-scrolling preference but never changes it. It does not ask for administrator or root access.

Only QA builds compute the last inferred source and reason or retain a bounded history of 16 scroll-state changes and filter resets: phases, pixel/line format, inferred source, reversal and the **sign** of the incoming impulse. Conflicting vertical signs are shown as 0; identical states are counted. A separate QA-only list keeps up to 16 eligible wheel samples: line/point/raw delta values after the direction stage, time between inputs, planned distance, immediate distance and mode. Wheel and autoscroll frame, timing and delta counters are QA-only as well. Production does not retain the QA histories or frame counters. It currently calculates a transient wheel-sample interval and, during deferred motion, a maximum frame gap in memory; these are hidden from the production UI. These values are not saved or transmitted. The scroll diagnostics contain no typed content, pointer positions or app names. The additional QA-only Home/End snapshot contains the last navigation keycode, modifier bits, focus classification, app bundle ID/PID and routing status; no letters or text payload are recorded. These diagnostics have no built-in export, disk log or network transmission.

QA also retains the latest middle-click target category (link, native control, ordinary content or unknown) and latest/maximum lookup duration. This is one transient category and two timing values, with no list of clicks or page data. Production leaves this collection disabled.

Dense-input adaptation keeps only recent timing, direction, a saturated interval count and response state on the worker; it performs no additional device queries. The QA wheel sample also holds a boolean for the dense state, within the existing 16-sample limit. This does not identify a Logitech model or mechanical wheel mode.

Frame templates briefly retain an event's position, modifier flags and target PID on the worker so deferred motion keeps the original routing context. Pointer, click, modifier and foreground-app changes cancel the pending tail. The read-only HID inventory informs the optional trackpad policy; it is not a per-event device identity.

Smooth-mode display links read the connected-screen inventory to select frame cadence. They add no input event types or new permission category. QA exposes only a transient clock kind (display link, timer, or idle) alongside the existing timing counters; it does not record a screen inventory or pointer history.

## Optional local terminal setup

Only after the user confirms **Terminal einrichten**, ScrollFix installs its bundled zsh selection module in `~/Library/Application Support/ScrollFix/` and adds a marked loader section to `~/.zshrc`. It reads the existing startup file to preserve it and stores a private exact backup. It also checks an already installed configuration on app startup. These files are never transmitted or logged. Unexpected ownership, symbolic links, custom startup locations and malformed managed blocks prevent automatic setup. The module adjusts zsh line-editor bindings only; it launches no commands, reads no input files, writes no history and has no network or clipboard access. See [setup and removal](TERMINAL.md).
